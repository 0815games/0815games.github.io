# Automatic player search

The search visibility toggle was removed. The current client creates or restores the player's searchable name listing automatically after their account profile loads, including profiles that previously had search visibility disabled. Exact-name search is case-insensitive; duplicates remain distinct and friend requests require acceptance. Signed-in players can see the matching soldier name, player ID and internal friend token. They do not gain access to the player's private profile or online presence through search. There is still no blocking or server-side request rate limiting.

**Existing accounts that have never published a listing cannot be backfilled by this client while their owners are offline:** the database rules protect profiles and only the owner can create their search listing. Each existing account must sign in once with the updated client (or an administrator must run a separately reviewed privileged migration). Index creation failures show a retry message. Existing listings, friendships, and invitations remain intact. A user on an outdated client can still hide their listing under the currently published rules; the current client restores it when they next sign in. A server-side account creation/indexing service would be needed for a stronger always-indexed guarantee.

This change uses the already published `coop-invites.complete.draft.rules.json`; it does not require a Firebase rules replacement. Verify with two real accounts: reload both, sign in without opening Friends, search each exact name, send/accept a friend request and invite to a co-op party; also test an account whose listing was formerly hidden and a connection failure/retry. Emulator tests do not prove production behavior.
