# Friend presence rollout

`friend-presence.complete.draft.rules.json` is a complete replacement based on the previously published direct-invites draft, adding only `friendPresence`. Before publishing, export and back up the current production Realtime Database rules, compare them with `direct-invites.complete.draft.rules.json`, and reconcile any production-only changes. Review and publish the complete replacement in the Firebase console **before deploying the client**. Do not assume production currently matches the draft. No service credentials are stored here.

Each signed-in client registers a random per-tab connection with server timestamps and on-disconnect cleanup; timestamps expire after three minutes if cleanup fails. Only the owner writes their own status; only the owner and accepted friends may read it. A missing record is displayed as "Offline or using an older version", not proof the person is offline: both users must reload the updated client. A connection, permissions or clock error is shown as status unavailable. Invitations remain possible when status is offline or unknown; this is advisory, not an authorization check. Presence means connected to Firebase, not that the player is watching the screen or available to play. Client clock skew, multiple tabs, network changes and abrupt shutdown can affect accuracy.

After publication and client release, verify with two real accounts and browsers: accepted and unaccepted friend visibility; both friendship directions; multiple tabs; reload, sign-out and disconnect; offline/old clients; reconnect; invitation delivery in each status; revoked friendship; and failure to read/write presence. Emulator tests do not replace real-device tests.
