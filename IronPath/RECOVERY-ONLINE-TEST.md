# Limited online host-recovery test

This is a controlled trial, not a general release. The latest complete repository rules are `firebase/doctrines.complete.draft.rules.json`: they include story progress, multiplayer, recovery paths and extended skills. The user reported publishing these rules, but live database contents have not been independently verified. Do **not** publish older partial or complete drafts: they may lack current story or skill support. Firebase replaces the entire ruleset on publication. Before any rules deployment, back up and compare the actual live rules, merge any independent changes and run the complete story emulator suite. Never publish a fragment. Emulator tests do not replace real-device testing.

On the deployed GitHub Pages client:

1. The host opens `https://0815games.github.io/IronPath/?recovery=1` and signs in. This opts the **host's new party** into recovery; the regular URL continues to create normal parties. All participants should refresh to the latest version before joining. The started manifest tells current guests which protocol to use, even if they open the normal URL.
2. Under Multiplayer, create a party, note its four-digit code, and approve one other signed-in player. Begin a short co-op match and perform a build or start a wave.
3. Reload the host browser without signing out or closing the party. The guest should wait. The host signs back into the same account if necessary, opens Multiplayer, enters the same code and selects **Resume as Host**. Verify that the same battle resumes and the guest can act. Commands in flight may be cancelled or reported as uncertain rather than repeated.
4. Close the party normally after the test, and report unexpected errors, timing, device/browser details and whether the guest remained connected. Don't post account credentials or the party code publicly. Test the other modes and reconnect scenarios separately.

Do not use this trial for important runs. The prototype commits full checkpoints and recipient views up to five times a second during active play, approximately 250 MB per hour written in one simple four-player local example, before downloads and protocol overhead. Commands may wait up to roughly 200 ms for a batch, plus database latency; slower commits can slow simulation. Keep initial tests short, monitor Firebase usage and quotas, and stop if costs or errors rise. Real device/network behavior, abandoned-party cleanup, and broad-scale traffic remain unverified; host-controlled simulation and rewards are not cheat-proof. Trial recovery history fails closed after 64 takeover attempts, and a failure before the initial checkpoint exists cannot be resumed.
